# 骨架（第 1 步）和结尾（第 3 步）

**不写成稿。** Park 有完整的原文，中间怎么讲是他自己的事。骨架只给他一个人不好做的：把原文拆成**论点 + 证据**，判断够不够成一篇，再给一句结尾。开头候选见 `开头.md`。

## 先看够不够成一篇

拆之前先回答三个问题，有一个答「没有」就在骨架最上面写出来，交给 Park 定还做不做，不要等到配完图、QA 才发现：

- **有主线吗？** 能不能用他原文里的一句话说出这篇在讲什么。
- **有递进吗？** 后一段是不是接着前一段往下走，还是几段话堆在一起。
- **有结尾吗？** 他讲完了，还是说到一半。

一段讲话的片段（「放这个视频」「你可以看到我的屏幕」、三五句就断了）不够成一篇。10/11《所有功能都是基于我自己的需求》就是这样发出去的：没有主线、没有结尾。

## 论点 + 证据

**用 Park 原来的逻辑顺序**，不重排。一般 3–5 个论点，每个写两行：

```
### 论点 X：<一句话，就是他原文里的判断>
证据：<撑这个判断的东西>
```

证据只有两种写法：

1. **原文 / 素材里真有的**：直接写出来是什么（他做过的事、他经历的一次失败、可回读的过程）。
2. **原文里没有的**：写成**一行具体的待办**，说清去拍什么、截什么图、查什么数，并标它属于证据单的哪一类（见 `配图.md`）。

> 证据：要补（截图）—— 去后台截一张「近 30 天收入构成」的图，圈出哪部分是你本人在场才赚到的。

**绝不许把没有的写成好像已经有。** 也不要写「需要补充案例」这种没法执行的话。

**分清五件事**：生成、跑通、发布、被使用、产生收入是五件事。工具截图不是结果。

## 选一个骨架

整理（第 4 步）时按骨架挪段落；在改动说明里写用了哪个。

| | 适合 | 顺序 |
|---|---|---|
| **A 结果数字 + N 条**（默认） | 方法论、赚钱路径、几条路 / 几个坑 | 带数字的开头 → 凭什么信你 + 「总共就 N 条」 → 每个论点后面紧跟一条他自己的证据 → 一句回扣开头的数字 |
| **B 亲历 + 判断** | 观点、人生判断、行业内幕 | 一句定性判断或「讲出来会被骂」 → 他自己的一个具体场景，带时间 / 钱 / 粉丝数 → 先判断再故事 → 「不是 X，而是 Y」 |
| **C 先看成品** | 演示工作台、skill、工具、工作流 | 「你现在看到的是……」 → 很多人觉得一般，是因为…… → 「我把最常用的 N 个给你」 → 每步一个结果画面 → 回到开头的成品 |

原文的段落排不进这个顺序，就别硬排，保持原顺序。

## 结尾

**一句话**，做两件事：

1. **兑付开头。** 开头许诺了什么（一个数字、一个判断、一个方法），结尾把它给出来并回扣一遍。
2. **收住。** 落在一句判断、一个具体画面，或「了解自己」，不落在总结上。

- Park 的备注里给了承接（「如果你有私域流量但不知道怎么变现，欢迎来找我」）就用他的原话；没给就只写一句判断收束，引导语写「结尾：你自己定」，不替他生造。
- 不加稀缺性和催单（「仅此一场」「错过就没有了」）——一勾结尾催得最硬的那条只有 0.5×，最爆的那条一个 CTA 都没有。
- 原文结尾有「关注我」「来上课」，不删，标出来让他定。
- 系列内容的 CTA 按系列框架走（比如系列 1：评论区留言领免费，不放微信、不放站外链接）。

## 通用禁止

- 增加素材里没有的经历、数字、客户结果或收益；
- 把个人判断伪装成已经证实的事实；
- 为了冲突把结论写得比证据更绝对；
- 讲课口吻；把观众写成无知的人；
- 写成稿——这一步只要骨架。
